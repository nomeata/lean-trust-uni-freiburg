# Lean – Architecture, Meaning and Trust

Slides for a talk at Universität Freiburg, built with
[Verso Slides](https://github.com/leanprover/verso-slides) (reveal.js).
Setup and style follow Leo de Moura's SViL 2026 deck.

## Abstract

The Lean theorem prover is suddenly in every mathematician’s news feed, because the sudden surge of proofs that AI companies are producing to show off are often accompanied by a formal Lean proof. But what does it mean to have a “Lean Proof”? What is Lean anyways, and why should I trust it?

We’ll give a very brief glimpse into a Lean proof, with a focus on its architecture with a large, untrusted elaborator and a small, trusted kernel. We’ll make sense of Lean’s fundamental type theory, and how it relates to the set theory that mathematicians may be more familiar with. We’ll go through the practical and theoretical aspects to the question “can I trust this proof”, touching on the dangers of “malicious” proofs, the need for external Lean checkers, how such checkers can themselves be verified, and why despite all this, one still needs to very carefully read theorems.

## Files

- `Slides.lean` — the slide content
- `Main.lean` — build driver: runs Verso Slides, then copies `static/` and
  post-processes the HTML (stylesheets, inlined SVG figures, offline use)
- `static/` — CSS, fonts, logos, images

## Building

    ./serve.sh            # live preview on http://127.0.0.1:8000/, rebuilds on save
    ./build.sh            # HTML into _slides/
    ./build.sh --pdf      # also out/lean-trust-freiburg.pdf

The figures in `static/images/` are generated by `tools/figures.py` (which needs
TeX) and committed, so the GitHub Pages workflow (`.github/workflows/pages.yml`)
only runs `lake build` and `lake exe lean-trust-freiburg-slides`.

Dependencies (elan, a C compiler, python, node, chromium, pdfunite) come with
`nix develop`; run `npm install` once for playwright.
